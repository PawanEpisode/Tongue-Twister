## 0. Decisions (added to `11` as D20–D23 by api-core)
- **D20 Score cards have their own flag `score_cards`** (seeded **on**, kill switch). They store no media, so they must not wait for Supabase Pro (`share_links` stays tied to recordings). The score-card endpoints (`POST /attempts/{id}/score-card/`, `GET /public/s/{token}/`, the image endpoint) check `score_cards`, not `share_links`.
- **D21 Account deletion has a 30-day grace period** (`ACCOUNT_DELETION_GRACE_DAYS=30`). On request the account is *pending deletion*: share links are revoked at once, public pages 410, the profile leaves the boards, reminders stop, and writes are blocked except cancel/export. Nothing is purged until the grace period ends, so the user can cancel. After it: media objects are deleted from storage first, then the Profile row (cascade), then the Supabase Auth user (Admin API). This deliberately deviates from D14's "media purged ≤ 24 h of the request": D14's 24 h now counts from the end of the grace period. The consent log cascades with the profile; whether it must be retained longer is a **legal question for the owner**, noted in `12`.
- **D22 Export is a direct JSON download** (`GET /me/export/`), not an emailed zip: no media bytes, only metadata.
- **D23 Night owl mode** shifts the *streak day boundary* to 03:00 local for opted-in users (activity 00:00–02:59 counts for the previous local day). The shift lives in exactly one function (`localtime.local_date`) so streaks, `DailyActivity`, mastery days and summary all agree.

### 1.1 Score-card images (A1)
- New flag `score_cards` (migration seed, on). Replace the `share_links` gate on the three score-card endpoints (see D20). Tests prove `share_links` off + `score_cards` on works, and the reverse is 403 `feature_disabled`.
- `GET /public/s/{token}/image.png?size=og|square` 🔓: `og` = 1200×630, `square` = 1080×1080 (default `og`; other value 400). Rendered server-side with **Pillow** (add `pillow` to `requirements.txt`) in a new `twisters/media/scorecard.py` (pure function `render(payload, size) -> bytes`, no DB access, deterministic). Content: wordmark "Twister", score ring with the number, twister text excerpt (≤ 120 chars, word-wrapped, ellipsis), accuracy %, WPM, `owner.display_name` **only** from `public_name` (blank ⇒ omitted), no avatar, no media, no e-mail. Bundle an open-licence font under `api/twisters/assets/fonts/` with its licence file (copy DejaVu Sans / Bold from the system if present; verify the licence permits redistribution; the serverless host has no system fonts). Resolve the token with the **same resolver** the JSON endpoint uses (reuse; do not copy), so 404/410/kill-switch/expiry behave identically (404 unknown, 410 expired/revoked/target deleted, 403 `feature_disabled` when the flag is off). Headers: `Content-Type: image/png`, `Cache-Control: public, max-age=3600`, strong `ETag` (hash of the rendered payload inputs; honour `If-None-Match` → 304), `X-Robots-Tag: noindex, nofollow`. Throttled with the existing share-resolve throttle. Never log tokens.
- `GET /public/s/{token}/` gains `images: {"og": "<abs url>", "square": "<abs url>"}` built from `settings.API_PUBLIC_URL` (new setting, env `API_PUBLIC_URL`, default `http://localhost:8000` in dev; in production required only when score cards are used — if unset, omit `images`) and `owner: {"display_name": <public_name|null>}`.
- Tests: PNG magic + exact dimensions for both sizes, image is not blank (≥ 3 distinct colours), long twister text and unicode do not crash, 304 on matching ETag, 410/404/403 parity with the JSON endpoint, no `display_name`/e-mail ever rendered (render with a profile that has both and assert on the `payload` passed to `render`), flag semantics.

### 1.2 Data export + account deletion (A2)
New package `twisters/account/` (`export.py`, `deletion.py`, `authadmin.py`, `serializers.py`, `views.py`); thin views.
- `GET /me/export/` 🔐 → `200 application/json`, `Content-Disposition: attachment; filename="twister-export-YYYYMMDD.json"`, `Cache-Control: private, no-store`, throttled 3/hour/user (new throttle). Body `{"schema_version":1,"generated_at":…,"truncated":false,"profile":{…},"preferences":{…},"favorites":[slug…],"attempts":[{…,"words":[…]}],"sessions":[…],"daily_activity":[…],"stats":{"twisters":[…],"words":[…],"phonemes":[…]},"achievements":[{code,unlocked_at}],"recordings":[{metadata only}],"consents":[{type,version,granted_at,revoked_at}]}`. Hard cap `EXPORT_MAX_ATTEMPTS=20000` newest first, `truncated:true` when hit. **Never** include: other users' data, token hashes, `ip_hash`, storage paths/buckets, signed URLs, worker/internal fields, audio hashes, nonces. Build with iterator/chunked queries (no loading everything at once); a leak test walks the JSON for forbidden keys.
- `DELETE /me/` 🔐 body `{"confirm":"DELETE"}` (anything else 400) → `202 {"deletion_requested_at","deletion_scheduled_for"}`; idempotent while pending (same dates). `DELETE /me/deletion/` (or `POST /me/deletion/cancel/` — pick one, document it) cancels → `200`; allowed any time before the purge. New fields `Profile.deletion_requested_at`, `Profile.deletion_scheduled_for` (nullable; CHECK scheduled ≥ requested). On request: revoke all `ShareLink`s, set recordings `hidden`-equivalent so public pages 410 (reuse existing hold/revoke services), exclude from boards (reuse `hide`-style filters: add one `Profile.objects.active()` / queryset helper rather than scattering `deletion_requested_at__isnull=True`).
- **Pending accounts**: in the single authentication step (`auth.py`) a pending profile may only use safe methods plus `DELETE /me/deletion/`, `GET /me/export/`, `GET/PATCH /me/` (PATCH only to cancel is not needed — keep PATCH allowed? **No**: block it); everything else non-safe → `403 account_pending_deletion` (new error helper, `details.scheduled_for`). `GET /me/` and `GET /me/summary/` carry `deletion_scheduled_for`.
- `purge_deleted_accounts` management command (workflow allow-list + cron hourly at `:53`, add to `manage-command.yml` exactly like the others): for each profile with `deletion_scheduled_for <= now`, in its own transaction: hard-delete all media objects from storage **inline** (reuse the hard-delete pass of `expire_recordings`/`purge_profile_media`; do not duplicate it), release the ledger, and only when every object is gone delete the Profile (cascade) then call `AuthAdmin.delete_user(id)`. A storage failure leaves the profile pending and retries next run (log, no crash). `AuthAdmin` = tiny adapter over stdlib `urllib` like `SupabaseStorage`, injectable transport, uses `SUPABASE_URL` + `SUPABASE_SERVICE_ROLE_KEY` (`DELETE {SUPABASE_URL}/auth/v1/admin/users/{id}`); a 404 from Supabase counts as success; key unset ⇒ skip with a warning (dev/tests use a fake). Never log the key.
- Tests: export shape + leak test + cap + throttle + other-user isolation; delete confirm gate, idempotency, cancel, grace maths with a fake clock, write-block matrix (a representative route per area), share links revoked + public 410, boards exclusion, purge picks only due profiles, storage failure keeps the profile, cascade really removes attempts/stats/consents, Supabase 404 ok, key-less skip, command idempotent.

## 2. api-ops — API hardening (owner of: `security.py`, `config/settings.py` security/Sentry block, `worker/` signer + its tests, `docs/runbooks/`, `docs/features/16-…` is NOT yours)

### 2.1 Signed worker callbacks with a timestamp (A4)
All HMAC endpoints (`/internal/scoring-jobs/…`, `/internal/media/…`) via the one helper `security.require_worker_signature`. New scheme: header `X-Worker-Timestamp: <unix seconds>`; signature = `HMAC-SHA256(secret, f"{ts}.".encode() + body)`, still sent as `X-Worker-Signature: sha256=<hex>`. Reject if `|now − ts| > WORKER_SIGNATURE_MAX_SKEW_S` (300) → `403`. Legacy signatures (no timestamp header) are accepted only while `WORKER_ALLOW_LEGACY_SIGNATURE=1` (default **1** so deploy order is safe; the runbook says flip to 0 once the worker is redeployed). Constant-time compare. Update the worker's signer (`worker/`) to send the new scheme, regenerate the shared test vector used by `tests/test_worker_signing_vector.py` and the worker's own test (both sides assert the **same** vector), and keep the legacy vector test while the flag exists. Tests: valid, tampered body, wrong secret, missing/old/future timestamp, legacy on/off, replay inside the window is **documented as not prevented** (stateless serverless) — add the sentence to the runbook, do not invent a cache.

### 2.2 Sentry for the API + PII scrubbing (B3, API half)
`sentry-sdk[django]` added to `requirements.txt`; init in a new `twisters/observability.py` called from settings **only when `SENTRY_DSN` is set** (no network and no import cost otherwise). `send_default_pii=False`, `traces_sample_rate=SENTRY_TRACES_SAMPLE_RATE` (default 0.0), `release` from `VERCEL_GIT_COMMIT_SHA` or `SENTRY_RELEASE`, `environment` from `SENTRY_ENVIRONMENT` (default `production`/`development` by DEBUG). A `before_send` scrubber (pure, unit-tested) that removes: `Authorization`/`Cookie`/`X-Worker-*` headers, request bodies for `/attempts/` and everything under `/internal/` (transcripts, audio hashes), query strings that carry tokens, path segments that are share/unsubscribe tokens (`/public/r/<token>`, `/public/s/<token>`, `/public/unsubscribe/<token>` → `<token>`), signed-URL query params, e-mail addresses anywhere in messages/breadcrumbs (regex), and `user` ⇒ only the Supabase `id` (no e-mail/ip). Tag `request_id` (the existing `X-Request-Id`). Ignore expected 4xx `ApiProblem`s (they are not crashes). Tests: scrubber table (input → output), init is a no-op without DSN, init does not send (use the SDK's test transport / `transport` stub), expected errors filtered.
