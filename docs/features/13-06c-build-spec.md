# 13 — 06c Build Spec (Record, media, sharing, consent)

Binding spec for the 06c slice. Sources: `04` (PRD), `06c` (ERD), `07` §6/§7/§10/§11 (contract), `09` E4/E5, `11` D1/D2/D6/D7/D14. Where this file and `07` differ, **this file wins** (it is what gets built); after shipping, fold it into `07` + `12` and delete nothing else.

## 0. Scope decisions
- Everything in 06c ERD ships: `Recording`, `MediaAsset`, `StorageLedger`, `ShareLink`, `UserConsent`, `ModerationReport` (+ migration M4), `Profile.age_band`.
- Layouts L1–L7 all ship (L4 screen+bubble, L7 element/region capture are Chromium/desktop-only, capability-detected).
- **Storage is behind an adapter** (`StorageBackend`): `SupabaseStorage` for prod, `InMemoryStorage` for tests/dev. No test may touch the network.
- **No FFmpeg worker container in this slice.** `POST /internal/media/{asset_id}/processed/` (HMAC) exists so the worker can plug in later. While `MEDIA_PROCESSING_ENABLED=0` (default) `complete` marks the recording `ready` directly (PRD 04 §10 "MVP can skip transcode").
- `POST /recordings/{id}/analyse/` is **not built** (needs the worker engine). Analysis is client-side: the web app creates a normal `kind=record` attempt and links it (`attempt` field on create/PATCH).
- Flags (seeded in migration, kill switch = `enabled=false`): `record_local` ON, `record_screen` ON, `record_region` ON, `record_cloud` OFF, `share_links` OFF (turn on only after Supabase Pro, D7). `GET /flags/` already exists; web `DEFAULT_FLAGS` mirrors.
- Numbers live in `Plan.limits` / settings, never inline (D1): `free` = `{recordings_max:5, recording_ms_max:180000, storage_bytes_max:104857600, retention_days:30, share_max_days:7}` + `voice_clip_ms_max:60000, voice_clip_bytes_max:2097152`.

## 1. API (Django, `api/twisters/media/` package)
Module layout (one responsibility each, no logic in views):
`storage.py` (adapter + fake + `get_storage()`), `consent.py`, `quota.py` (ledger reserve/reconcile/release under a per-user `select_for_update` on `Profile`), `uploads.py` (create asset + signed upload; verify on complete — shared by recordings and voice clips → DRY), `recordings.py` (create/complete/update/delete/restore/expire), `shares.py` (128-bit token, sha256 hash, constant-time resolve), `moderation.py` (report, auto-hide at 3 distinct reporters), `serializers.py`, `views.py`, `throttles.py` additions, `jobs` = management commands `expire_recordings`, `orphan_sweeper`.
Cross-cutting: reuse `errors.ApiProblem` (add `quota_exceeded` 402, `minor_not_allowed` 403, `dependency_unavailable` 503 helpers next to `consent_required`), the existing HMAC check used by `speak.scoring_job_result` (extract to a shared helper — do not copy), `practice.flags.enabled`, `WindowedRateMixin`. `Attempt.voice_asset_id` and `ScoringJob.audio_asset_id` become real FKs to `MediaAsset` (`SET_NULL`, same column) and the word-feedback audio donation now requires `model_improvement` consent instead of always 403.

| Endpoint | Auth | Behaviour |

| `POST /recordings/` | 🔐 | Flag `record_cloud`; `age_band` must be `13plus` (`minor_not_allowed`; `unknown` → `403 age_required`); consent `recording_upload` at current version else `consent_required`; enforce plan count/duration/bytes → `402 quota_exceeded` (details name which limit); size > `MEDIA_MAX_BYTES` → 413; mime not `video/webm|video/mp4` → 415. Making `unlisted` needs no link; links are separate. |
| `DELETE /recordings/{id}/` · `POST /recordings/{id}/restore/` | 🔐 | Soft delete (revokes its ShareLinks, ledger release **deferred to hard delete**), restore within 24 h. |
| `POST /recordings/{id}/retry-processing/` | 🔐 | Only when `failed`. |
| `POST /voice/` + `POST /voice/{asset_id}/complete/` | 🔐 | Same `uploads.py` path with `kind=audio`, limits from plan, consent `voice_storage`; auto-expires 30 d; returns `voice_asset_id`. |
| `POST /recordings/{id}/share/` `{expires_in:"24h|7d|30d"}` | 🔐 | Flag `share_links`; recording must be `ready`, not reported/hidden, owner `13plus`; expiry ≤ `plan.share_max_days`; returns `{id,url,expires_at}` with the raw token **once** (`SHARE_BASE_URL` + `/r/<token>`). |

## A2. API additions (`twisters/media/`)
1. **Job queue** — new model `MediaJob` (uuid pk, `recording` FK, `asset` FK to source `MediaAsset`, `kind` = `process|analyse`, `status` = `queued|running|done|failed`, `tries`, `max_tries=3`, `locked_until`, `error_code`, timestamps; partial index on queued/running; unique partial `(recording, kind)` where status in queued/running so enqueue is idempotent). `complete` enqueues `process` when `MEDIA_PROCESSING_ENABLED=1` (recording `processing`), else behaves as today. A sweeper pass (inside `orphan_sweeper`) re-queues jobs whose lease expired and fails those over `max_tries`.
2. **Worker endpoints (HMAC, no user auth)** — final shapes as built (binding for `worker/`). All three send/verify `X-Worker-Signature: sha256=<hex HMAC-SHA256 of the raw request body>` with `WORKER_SHARED_SECRET` (an empty body is fine: sign the empty string). `503` if the API has no secret, `403` on a bad signature. They are not rate-limited.
   - `POST /api/v1/internal/media/claim/` (body `{}` or empty) → `200 {"job": null}` when nothing is queued, else
     ```json
     {"job": {
       "id": "<uuid>", "kind": "process" | "analyse",
       "recording_id": "<uuid>", "asset_id": "<uuid of the source video asset>",
       "lease_s": 120,
       "source": {"url": "<signed GET url>", "mime": "video/webm", "size_bytes": 1234567},
       "outputs": {
         "mp4":       {"bucket": "recordings", "path": "...", "upload_url": "...", "token": "...", "mime": "video/mp4"},
         "thumbnail": {"bucket": "thumbs",     "path": "...", "upload_url": "...", "token": "...", "mime": "image/jpeg"},
         "captions":  {"bucket": "captions",   "path": "...", "upload_url": "...", "token": "...", "mime": "text/vtt"}
       },
       "words": [{"target": "she", "start_ms": 120, "end_ms": 480, "status": "correct"}] | null,
       "limits": {"max_height": 1080, "max_s": 900}
     }}
     ```
     `process` jobs get `outputs.mp4/thumbnail/captions` (and `words` when the recording has a linked attempt, else `null`); `analyse` jobs get only `outputs.audio` = `{…, "mime": "audio/wav"}` (16 kHz mono WAV) and `words: null`. `source.url` is a signed GET valid `MEDIA_WORKER_URL_TTL_S` (1800 s). To upload an output: `PUT <upload_url>` with the raw bytes and `Content-Type: <mime>` (the `token` is already inside `upload_url`; it is given separately for TUS clients). The thumbnail must be a JPEG ≤ 200 KB (`THUMBNAIL_MAX_BYTES`); captions are WebVTT starting with `WEBVTT`; `mp4` must have an `ftyp` box; `audio` is RIFF/WAVE and may be large (only `MEDIA_MAX_BYTES` applies). Output paths are deterministic per job, so re-uploading after a crash overwrites (the signed URLs allow upsert). `words` holds the target words in order (extras excluded); `start_ms/end_ms` may be `null` (e.g. missed words) and `status` is `correct|near|wrong|missed`. A claim takes a lease of `lease_s`; `tries` is incremented on every claim (max 3).
   - `POST /api/v1/internal/media/jobs/{job_id}/heartbeat/` (body `{}`) → `200 {"job_id", "lease_s", "locked_until"}`; `404` unknown job; `409 lease_lost` when the job is no longer running (finished, failed or re-queued) — the worker must abandon it. Send one roughly every `lease_s / 3`.
   - `POST /api/v1/internal/media/{asset_id}/processed/` (`asset_id` = `job.asset_id`), idempotent:
     ```json
     {"job_id": "<uuid>", "status": "ready" | "failed",
      "duration_ms": 41200, "width": 1280, "height": 720,
      "outputs": ["mp4", "thumbnail", "captions"],
      "error": "ffmpeg_failed", "retryable": true}
     ```
     `outputs` lists the slots that were actually uploaded (`["audio"]` for analyse; omit `mp4` when the original is already H.264/AAC MP4 and was not re-encoded). `duration_ms/width/height` describe the playback video and are optional. `error` (≤ 60 chars, no free text) and `retryable` (default `true`) are used only for `failed`. `job_id` is strongly recommended (without it the recording's latest `process` job is used). The API stats each declared output itself (size, magic bytes), so nothing in the body is trusted for paths. Response `200 {"status": "<echo>", "job_status": "done|queued|failed"}`; a repeat of a settled result returns `200` + `Idempotent-Replay: true`. `409 upload_incomplete` = a declared output is not in storage yet (re-upload, then call again); `410` = the recording was deleted (drop the job). A failed job with `retryable` and tries left goes back to `queued`; otherwise the job and the recording fail (`failure_reason` = `error`).
3. **`POST /recordings/{id}/analyse/`** 🔐 (flag `record_cloud`, consent `voice_processing`, 13+, recording `ready|processing`): idempotently enqueues an `analyse` job (worker produces the 16 kHz audio asset) → `202 {analysis:{status:"queued|running|ready|failed", audio_ready:boolean}}` (`200` + `Idempotent-Replay` when a job is already waiting or the audio already exists); `GET` of the recording detail carries the same `analysis` block, with `status:"none"` (and `audio_ready:false`) when nothing was requested or the audio has been purged. As built it also needs `MEDIA_PROCESSING_ENABLED=1` (`403 feature_disabled` otherwise) and the analysis WAV is kept `ANALYSIS_AUDIO_RETENTION_DAYS` (7) and removed with the take or when `voice_processing` consent is withdrawn. The scoring step that turns that audio into an `Attempt(kind=record)` belongs to the doc-10 scoring worker and is NOT built here — document this clearly in `12`; the web app keeps creating the attempt client-side.
4. **Expiry reminder email**: Django email (`EMAIL_BACKEND`/`EMAIL_*` env, console backend in dev, `DEFAULT_FROM_EMAIL`), `send_expiry_reminder()` becomes real: one email per user per batch of recordings expiring in ≤ 3 days, idempotent via `Recording.reminder_sent_at`, skipped when the profile has no email, opt-out respected via `UserConsent(type=marketing)`-independent transactional rule (it is transactional, always sent) but with a signed one-click "keep for 30 more days" link is NOT built — just a link to `/recordings`. Text + minimal HTML template in `twisters/media/templates/`. Run from `expire_recordings`.
5. **Privacy hardening**: (a) `Profile.public_name` (≤ 40, blank default, opt-in, profanity/blocklist check reusing the leaderboard filter if it exists else a small shared `validate_public_name`), settable via `PATCH /me/`; public endpoints return `owner.display_name` **only** from `public_name` (never `display_name`/email); (b) storage paths become opaque: `{hmac_of_profile_id[:16]}/{yyyy}/{mm}/{asset_id}.{ext}` — note this changes the Storage RLS sample in `storage_policies.sql`: owner folder can no longer equal `auth.uid()`, so RLS on `storage.objects` is **deny-all for clients** (all access via API-minted signed URLs, TUS uses signed upload token) — update the policies file + docs accordingly; existing rows keep their old paths (path is stored per asset, no backfill needed).
6. Tests for all of the above (fake storage, fake clock for leases, HMAC, SKIP LOCKED path guarded for Postgres), contract docs in `07` §14 and `12`.
